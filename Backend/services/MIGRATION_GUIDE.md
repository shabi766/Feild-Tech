# Microservices Migration Guide - Phase 1: Auth Service

This guide documents the migration of authentication functionality from the monolithic backend to a standalone Auth Service.

## What Was Migrated

### ✅ Completed

1. **User Model** (`services/auth-service/Models/user.model.js`)
   - Complete user schema with all fields
   - Supports all user roles and types

2. **Authentication Controllers** (`services/auth-service/Controllers/auth.controller.js`)
   - `register` - User registration with profile photo upload
   - `login` - User login with JWT token generation
   - `logout` - User logout
   - `forgotPassword` - Password reset OTP generation
   - `verifyOtp` - OTP verification
   - `resetPassword` - Password reset with OTP
   - `verifyToken` - Token verification endpoint for other services

3. **Routes** (`services/auth-service/Routes/auth.route.js`)
   - All authentication routes extracted

4. **Middleware**
   - Multer configuration for file uploads
   - Shared authentication middleware package created

5. **Utilities**
   - Database connection utility
   - S3 upload utility

## Service Configuration

### Port
- **Auth Service**: 8001 (configurable via `AUTH_SERVICE_PORT`)
- **Main Backend**: 8000 (unchanged)

### Environment Variables

The Auth Service requires the same environment variables as the main backend:
- `MONGO_URI` - MongoDB connection string
- `SECRET_KEY` - JWT secret (must match other services)
- `AWS_*` - AWS S3 credentials for file uploads
- `EMAIL_USER` / `EMAIL_PASS` - Email credentials for password reset

## Running the Auth Service

### Step 1: Install Dependencies

```bash
cd services/auth-service
npm install
```

### Step 2: Configure Environment

```bash
cp .env.example .env
# Edit .env with your configuration
```

### Step 3: Start the Service

```bash
# Development mode (with nodemon)
npm run dev

# Production mode
npm start
```

## Integration with Frontend

### Option 1: Direct Integration (Current)

Update your frontend API base URL to point to the Auth Service:

```javascript
// In your frontend API configuration
const AUTH_API_URL = 'http://localhost:8001/api/v1/auth';
```

### Option 2: API Gateway (Future)

Once the API Gateway is set up, routes will be:
- `/api/v1/auth/*` → Auth Service (port 8001)

1. Frontend is updated to use Auth Service

3. All services are migrated

## Troubleshooting

### Port Already in Use

If port 8001 is already in use, update `AUTH_SERVICE_PORT` in `.env`:

```env
AUTH_SERVICE_PORT=8002
```

### Database Connection Issues

Ensure MongoDB is running and `MONGO_URI` is correctly set in `.env`.

### CORS Issues

Update `FRONTEND_URL` and `API_GATEWAY_URL` in `.env` to match your frontend URL.

## Notes

- The Auth Service uses the same MongoDB database as the main backend
- JWT tokens generated by Auth Service are compatible with the shared middleware
- All user data remains in the same database collection
- File uploads use the same S3 bucket configuration
